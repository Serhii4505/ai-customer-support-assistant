# Прогресс проекта

## Реализовано и проверено
- Python API на FastAPI: /health и /chat.
- Сохранение сообщений и заявок в SQLite.
- Просмотр заявки по её номеру.
- Ответы из knowledge/faq.json по ключевым словам.
- Приоритет явного запроса менеджера над FAQ.
- Неизвестные вопросы направляются в очередь менеджера.
- Приветствия не создают запрос менеджеру.
- При указанном контакте помощник не просит его повторно.
- Очередь запросов менеджеру со статусом pending.
- Просмотр очереди и отдельного запроса.
- Завершение запроса: completed, исключение из ожидающей очереди.
- Сообщения из пробелов отклоняются с кодом 422.
- Пустые имя и контакт преобразуются в null.
- Все таблицы создаются при запуске, включая запуск с пустой базой.
- Соединения SQLite закрываются после каждой операции.
- Проверены сохранение данных, обработка очереди и удаление временной тестовой базы.
- Память имени и контакта по conversation_id, проверенная через API и n8n.
- Сохранение первого содержательного запроса без перезаписи последующими сообщениями.
- Благодарность не создаёт запрос менеджеру.
- Одна заявка на разговор с conversation_id; новые сообщения обновляют её контакт без создания дубликата.
- При запросе менеджера помощник использует сохранённую задачу и не просит описывать её повторно.
- Очередь и отдельный запрос менеджеру показывают исходную задачу даже без заявки.
- Контакт, добавленный позже в разговоре, отображается в ранее созданном запросе менеджеру.
- История сообщений теперь связана с `conversation_id`.
- Каждое сообщение сохраняется вместе с идентификатором разговора.
- Добавлен endpoint `GET /conversations/{conversation_id}/messages`.
- Проверено: один разговор корректно возвращает все свои сообщения по порядку.
- Добавлено автоматическое извлечение имени клиента из текста сообщения.
- Добавлено автоматическое извлечение email и телефона из текста сообщения.
- Добавлено извлечение исходной задачи клиента без приветствия, имени и контакта.
- Добавлен lead scoring: `cold`, `warm`, `hot`.
- `lead_score` сохраняется в SQLite и возвращается через API.
- Добавлена автоматическая обработка hot lead через n8n.
- n8n workflow проверяет `lead_score == hot`.
- Для hot lead отправляется Gmail-уведомление менеджеру с именем, контактом, задачей и lead score.
- Gmail OAuth подключён и протестирован.

## n8n
Проверена цепочка:
Webhook → HTTP Request → If → Respond to Webhook.

Обе ветки If возвращают ответ клиенту.
Webhook использует POST и путь customer-support.
Запуски проверены через тестовый адрес с Execute workflow.

Экспорт сценария:
workflows/AI Customer Support Assistant.json

## Текущие ограничения
- Режим demo: AI-модель ещё не подключена.
- FAQ и определение намерения работают по ключевым словам.
- Имя и контакт сохраняются между сообщениями, но ещё не извлекаются автоматически из текста.
- Полная история сообщений пока не связана с conversation_id.
- Нет оценки горячих лидов.
- Запрос менеджеру сохраняется локально; уведомления не отправляются.
- Повторная отправка создаёт новое сообщение.
- Нет авторизации для просмотра и изменения заявок.
- Производственный адрес n8n ещё не проверен.
